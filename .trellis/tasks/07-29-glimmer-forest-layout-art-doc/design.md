# 微光森林地图与贴图优化文档 - 设计方案

## 交付边界

本任务交付 Markdown 制作规范、用户原图的可重复加工流水线和森林首版运行时接入。剧情演出是视觉上游，现有地图玩法是功能边界；不修改服务端坐标、剧情状态和森林以外场景。

## 信息来源与优先级

1. 《开局剧情设计 V2.0》在开场任务 PRD 中记录的剧情事实与信息边界。
2. `S0_冷开场_月痕_缺失贴图生成提示词.md` 中的演出视觉机制和资产规则。
3. `WorldScene.ts`、服务端地图对象及测试中已经存在的玩法锚点。
4. 现有森林与开场资产的实际画面、尺寸和复用条件。

出现冲突时，剧情事实优先；地图视角和可玩性约束优先于直接复制 CG 构图；已有坐标只作为兼容参考，不在文档阶段冻结。

## 文档结构

正式文档按以下顺序组织：

1. 文档目标、适用范围与视觉一句话定义。
2. 演出到可玩地图的视觉翻译规则。
3. 当前地图与资产差距审计。
4. 地图总体布局和分区文本图。
5. 分区逐项设计与玩家动线。
6. 场景层级、深度排序、碰撞与遮挡规则。
7. 资产矩阵及现有资产处置表。
8. 统一风格提示词和单项资产提示词。
9. Must / Should / Defer 实施优先级。
10. 美术、程序和剧情联合验收清单。

## 地图布局模型

地图采用“入口缓冲 -> 可读主径 -> 中部选择点 -> 月光空地/核心古树高潮区”的叙事递进。采集支路和遗迹区从主径分叉后回接，避免死路过多；高浓度逆流雾从东南或右侧向核心古树汇聚，与树冠顺风方向形成对照。

布局示意只表达相对关系，不替代运行时坐标：

```text
西北：月光空地 / 露娜 / 核心古树
        |      断月雾核
遗迹区--+--雾区边缘--采集支路
        |          /
森林向导--中部主径--湿地采集区
        |
东南：村庄入口 / 回村出口
```

## 资产分层

- 地表层：冷湿腐殖土、苔藓、落叶和低亮微光纹理。
- 路径层：湿土、裸根、碎石和被踩伏的植被，边缘不规则。
- 中景可碰撞层：普通乔木、盘根、石块、树桩和遗迹组件。
- 叙事标志层：唯一核心古树、残缺断月刻痕、月光空地和证据节点。
- 动态氛围层：低位逆流雾、稀疏微光粒子和局部叶片运动。
- 前景层：树冠、枝叶和近景雾，限定遮挡范围并支持降透明。

## 复用策略

- `forest-obstacle.png`、`forest-stump.png`：可通过冷色调色和降低饱和度作为普通装饰复用，但需增加轮廓变体。
- `ancient-forest-tree.png`：不再作为整片森林通用树；可降级为风格占位，正式版本需拆分普通树组和唯一核心古树。
- `grass-ground.webp`、`dirt-path.webp`：仅保留晨曦村用途，森林应生成独立地表与路径纹理。
- `opening-s0-reverse-mist-overlay.png`、`opening-s0-broken-moon-mark.png`：作为风格参考；若运行时复用，必须处理黑底/透明通道、视角和性能问题。
- `opening-s0-reverse-mist-forest.png`：只作为色彩脚本和构图参考，不作为俯视地图底图。

## 验证方式

- 内容对照：逐项核对剧情不变量和现有玩法锚点。
- 结构检查：搜索 `TBD`、空章节、断开的相对路径和未闭合代码块。
- 数量检查：确认资产类别和提示词数量满足 PRD。
- 资产检查：验证 59 个输出尺寸、真实 Alpha、透明角点、manifest 和预览图。
- 运行检查：执行 type-check、生产构建和既有测试；浏览器检查资源加载、桌面/移动布局和森林画面。
- 对抗检查：从视角冲突、角色遮挡、路径误导、碰撞漂移、透明叠层性能和剧情泄露角度复核。

## 回滚

回滚时可分别移除版本化 `glimmer-forest-v1` 资产、预加载键和 `WorldScene` 的森林分支；村庄资源与布局保持独立，不需要整体回退地图系统。

## 多区域运行时扩展

### 数据流

```text
024_glimmer_forest_regions.sql
  -> map_data.resource_json(region_key, region_name, bounds, spawn, objects)
  -> GET /map/{id} 或 POST /map/enter
  -> MapData.resource
  -> GameShell 地图标题 + WorldScene 区域配置选择
  -> Phaser 地表、路线、碰撞体、装饰、特效和传送标记
```

API 保持透传 `resource_json`，不在 Python 服务层复制区域判断。数据库拥有地图连通关系，前端拥有纯视觉布局；`region_key` 是两者唯一共享的区域标识。

### 地图身份与兼容

- 部分1数据库名继续为 `微光森林`，新增 `region_name = 微光森林·部分1：月痕前庭`。
- 部分2至5使用独立地图名；开局服务、植物与剧情 SQL 仍只匹配部分1。
- 客户端对缺失或未知 `region_key` 的 `forest` 地图回退到部分1，兼容旧数据库和迁移未完成的本地环境。

### 前端配置边界

- 新建单一 `forestRegions.ts`，集中定义区域键、地表、路线、碰撞物、静态装饰、叠层特效和传送标记纹理。
- `WorldScene` 继续负责 Phaser 对象创建、深度、物理体和 reduced-motion；不把 Phaser 实例写入配置文件。
- `PreloadScene` 只注册五区域实际使用的版本化运行时资产。
- 部分1现有布局迁移到同一配置入口，但保留已有坐标、剧情证据位置和用户未提交的村庄路牌删除改动。

### 数据库迁移

- 新增连续迁移 `024_glimmer_forest_regions.sql`。
- 迁移使用 `ON CONFLICT (map_name) DO UPDATE`，随后以确定性 JSON 重建新增区域；部分1仅替换门户并保留非门户对象。
- 相邻地图门户成对创建；每个来源门户的 `spawn_x/spawn_y` 指向目标地图安全落点。
- `verify_schema.sql` 验证五个区域键和相邻双向边；API 流程测试实际走完部分1至5再原路返回。

### 降级与性能

- 大地表使用 tileSprite；完整盆地/庭院使用单张地面叠层，不重复平铺。
- 软特效限制在局部 Sprite/TileSprite，reduced-motion 下保留静态 Alpha、不创建无限 tween。
- 首版不加载全部 113 个成品，只加载区域配置实际引用的纹理。
