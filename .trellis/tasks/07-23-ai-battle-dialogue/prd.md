# AI 对战与对话接入

## Goal

为《斗萝大陆》新增一份可执行的 AI 接入设计文档，说明如何在不破坏现有
NPC 交互和回合制战斗闭环的前提下，引入 AI 驱动的对话与对战能力。

目标交付物为 `doc/AI对战与对话接入设计.md`。本任务只完成需求与技术方案，
不直接修改游戏客户端、服务端或数据库。

## Background

- 项目是 Vue 3 + TypeScript + Phaser 3 客户端、FastAPI + SQLAlchemy 服务端、
  PostgreSQL 数据库的 Web 游戏 Demo。
- NPC 当前通过 `npc_templates.reward.dialogue` 保存固定对白，客户端
  `DialogModal.vue` 按顺序展示文本。
- 战斗状态由服务端 `active_battles` 持久化；玩家通过出牌和结束回合接口推进战斗。
- 敌方当前不使用模型决策；玩家结束回合后，服务端按 NPC `battle_deck.attack`
  计算一次固定攻击。
- 战斗写操作使用 `battle_id`、玩家归属校验、数据库行锁和
  `expected_version` 保护状态一致性。
- 仓库当前没有 AI 模型供应商、模型配置、提示词、会话记忆或用量控制模块。

## Requirements

- 文档必须明确 AI 在对话和战斗中的职责边界，区分模型决策与服务端权威规则。
- AI 仅驱动非玩家角色：首期覆盖 NPC，后续怪物复用同一套 AI 能力边界；
  AI 不代替玩家出牌、移动、选择对话或执行其他玩家操作。
- AI 对话采用混合输入：玩家可输入自由文本，也可从两条快捷回复中选择一条发送。
- 两条快捷回复由 AI 根据 NPC 人设、当前对话和可用交互动态生成；模型失败、
  超时或输出不合格时，回退到策划为该 NPC 配置的固定选项。
- NPC 对话需要跨登录、跨设备保持有限记忆。记忆按“玩家 + NPC”隔离，
  保存有上限的近期消息和一段压缩摘要，不保存无限原文，不引入向量数据库。
- 记忆必须有明确的消息条数、摘要长度和保留期限上限，并支持后续清理。
- 自由文本必须设置服务端长度限制、发送频率限制和内容安全检查；客户端限制只作为体验辅助。
- 文档必须给出最小可行架构、端到端数据流、核心接口与数据契约。
- 文档必须覆盖模型超时、限流、返回非法结构、内容安全和服务不可用时的降级行为。
- 文档必须说明 API 密钥只保存在服务端，客户端不得直接调用模型供应商。
- 模型供应商通过 OpenAI-compatible API 接入，服务端使用环境变量配置
  `AI_BASE_URL`、`AI_API_KEY` 和 `AI_MODEL`，不在业务代码中硬编码供应商。
- 文档必须保持战斗数值结算、卡牌合法性、奖励和最终状态由服务端验证并写入。
- 文档必须说明对现有静态对话和固定敌方攻击的兼容与渐进启用方式。
- 文档必须给出分阶段实施顺序和可验证的测试清单。
- MVP 不引入独立微服务、消息队列、向量数据库或长期记忆平台，除非后续需求明确要求。

## Scope

### In Scope

- AI 对话生成的上下文、请求、响应、会话状态与降级策略。
- AI 驱动 NPC 及未来怪物的候选战斗动作、结构化输出、服务端校验与确定性回退。
- AI 对战只能从服务端根据当前战斗状态计算出的合法候选动作中选择，可返回角色化战斗台词，
  但不得创建技能、指定未经校验的目标、生成伤害数值或决定奖励。
- 服务端必须忽略模型输出中的额外字段，并重新校验所选动作；无效、超时或失败时执行确定性默认动作。
- 服务端配置、安全、日志、成本与延迟控制。
- 客户端需要展示的加载、失败、重试和降级状态。
- 客户端对话框需要提供自由文本输入、发送操作和两条快捷回复，并保留离开与发起对战操作。
- 推荐的接口、数据表或现有 JSON 状态扩展，以及实施和验证步骤。
- 跨会话有限记忆的数据模型、裁剪/摘要时机和读取边界。

### Out of Scope

- 本任务直接接入某个 AI SDK 或部署生产模型。
- AI 生成或修改战斗规则、奖励、玩家资产和数据库权限。
- 玩家之间的实时 PvP。
- AI 代替玩家操作或双方全自动对战。
- 语音输入输出、图片生成、多 Agent 编排和无限长期记忆。
- 语义向量检索、全局玩家画像和跨 NPC 共享私密对话内容。
- 为未来规模预建微服务、队列、缓存集群或模型路由平台。

## Acceptance Criteria

- [ ] 文档基于现有 NPC、战斗接口和版本控制机制描述改造点。
- [ ] 文档包含对话与对战两条完整数据流及核心请求/响应示例。
- [ ] 对话数据契约同时支持自由文本和两条快捷回复，且两种输入经过相同的服务端校验。
- [ ] 文档定义按玩家与 NPC 隔离的有限记忆、容量上限、摘要策略和清理机制。
- [ ] 文档规定模型只能提出内容或候选动作，服务端拥有规则和状态最终决定权。
- [ ] 对战响应契约只接受候选动作 ID 和可选台词，不接受模型提供的结算数值或奖励。
- [ ] 文档覆盖超时、限流、非法输出、重复请求、并发冲突和供应商不可用。
- [ ] 文档包含 MVP 实施阶段、测试方案、上线开关和回滚方式。
- [ ] 文档定义 OpenAI-compatible 配置、供应商适配边界以及不兼容结构化输出时的处理方式。
- [ ] 文档中的阻塞性产品决策已解决，不以未确认假设替代用户选择。

## Technical Notes

- MVP 对话采用同步 JSON 响应并展示加载状态，不引入流式传输；后续仅在实际延迟体验需要时增加 SSE。
- 现有 `httpx` 和 `pydantic-settings` 足以实现首个 OpenAI-compatible 适配器，
  无需立即增加供应商 SDK。
- 当前 `NpcTemplate` 同时承担 NPC 与战斗敌人配置；未来怪物模型出现时，
  通过服务层的统一 AI 战斗角色契约复用决策逻辑，不提前建立多态平台。
