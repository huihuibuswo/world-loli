## 3. 建议实现顺序

1. 先改服务端注册常量和测试，固定新初始资产契约。
2. 实现序章契约奖励函数及单元/集成测试。
3. 修改战斗结算分支，验证露娜无碎片、其他 Boss 仍有碎片。
4. 添加兼容迁移与数据库验证。
5. 扩展前端类型和战后剧情 UI。
6. 跑完整验证，并使用桌面与移动端截图检查剧情、奖励和退出按钮布局。

## 4. 验证命令

具体命令以仓库现有运行说明和环境为准，优先执行：

```powershell
Set-Location server
pytest tests/test_opening_story.py tests/test_battle_balance.py tests/test_card_spirit_fragments.py
```

```powershell
Set-Location game-client
npm run type-check
npm run build
```

数据库可用时执行现有迁移与 schema 验证流程，并确认：

- 玩家卡灵唯一约束仍生效；
- 玩家卡牌唯一约束仍生效；
- 定向迁移不触碰非旧默认套牌；
- 露娜序章契约胜利不新增碎片记录。

手动验收至少覆盖：

- 桌面端新号完整序章；
- 移动端战后五段对话、奖励区和返回按钮无重叠；
- 战后页面刷新可恢复剧情；
- 失败和中途退出后可重新挑战；
- 契约后收藏与启用套牌立即显示露娜和月牙撕裂。

## 5. Launch Blockers

- 新号仍能在序章前获得月牙撕裂或露娜。
- 露娜胜利同时发完整卡灵与碎片。
- 重复/并发结算产生重复卡灵、重复卡牌或重复套牌数量。
- 奖励部分成功但剧情或战斗状态未提交。
- 纯基础套牌无法在合理回合数内稳定完成露娜战。
- 战后剧情在刷新后丢失，导致玩家无法看完或无法离开战斗。
- 迁移覆盖玩家自建/已修改套牌或删除无法确认来源的资产。
