# 《斗萝大陆》游戏昼夜系统设计 V1.0

> 文档状态：首版设计方案  
> 适用范围：世界探索、NPC、战斗背景、存档与基础 UI  
> 核心原则：使用游戏内时间，不依赖玩家设备的真实时间

## 1. 目标

为《斗萝大陆》建立统一、可存档、可复现的昼夜循环，让晨曦村与微光森林在不同时段具有明确的视觉和玩法差异，同时避免昼夜系统阻断主线流程。

首版完成后，玩家应能感知到：

1. 游戏世界会从清晨、白天、黄昏自然过渡到夜晚。
2. 探索场景、战斗背景、环境光和 NPC 作息使用同一份时间状态。
3. 退出游戏后再次进入，游戏日期和时间能够正确恢复。
4. 关键剧情、任务交付和必要商店不会因时间永久不可用。

## 2. 现状与核心问题

### 2.1 已确认事实

- 世界探索由 Phaser 的 `WorldScene` 承载。
- 晨曦村与微光森林共用世界场景，但使用不同地图类型与资源。
- 晨曦村战斗已准备白天、夜晚两张背景图。
- `BattleScene.ts` 当前通过浏览器 `new Date().getHours()` 判断昼夜。
- 世界探索、NPC、任务和存档目前没有统一的游戏时间字段。

### 2.2 根因

当前的昼夜判断只是战斗场景中的局部视觉分支，不是世界状态。它会导致以下不一致：

- 玩家修改系统时间即可改变战斗背景。
- 世界地图可能显示白天，进入战斗后却显示夜晚。
- NPC 作息、剧情条件和环境效果无法共享同一时间。
- 存档不能记录“第几天、几点钟”，后续玩法没有可靠时间基准。

因此首版必须先建立唯一的游戏内时钟，再接入视觉和玩法表现。

## 3. 首版范围

### 3.1 Must

- 建立统一游戏时间：`day_index` 与 `minute_of_day`。
- 世界探索时推进时间，战斗、对话、菜单和加载期间暂停。
- 按时间阶段切换环境色、灯光、天空明度和战斗背景。
- 显示简洁的日期、时间和阶段图标。
- 保存并恢复游戏时间。
- 支持 NPC 显示与交互时段，但关键 NPC 必须提供兜底。
- 为剧情和采集系统提供可复用的时间条件，不在各模块重复计算昼夜。

### 3.2 Should

- 黄昏与清晨使用平滑颜色过渡。
- 夜晚开启村庄窗灯、路灯和局部月光。
- 微光森林夜晚增强银雾、月痕和冷色微光，但不遮挡路径。
- 在开发模式提供设置时间的调试入口。

### 3.3 Defer

- 天气、季节、月相和温度系统。
- NPC 完整日程寻路、回家与睡眠动画。
- 农作物跨日生长、商店每日经济模拟。
- 玩家睡觉、旅店休息和主动跳到指定时间。
- 离线期间继续推进游戏时间。
- 多人共享世界时钟。

## 4. 时间规则

### 4.1 时间比例

首版建议：

```text
1 秒现实时间 = 1 分钟游戏时间
1 个完整游戏日 = 24 分钟现实时间
```

这个比例能让一次常规游玩看见明显时段变化，同时不会让画面每几分钟就快速闪变。时间倍率应集中配置，不能散落在场景代码中。

### 4.2 时间阶段

| 阶段 | 游戏时间 | 主要表现 |
| --- | --- | --- |
| 清晨 `dawn` | `05:00-06:59` | 冷蓝转暖、低亮晨雾、灯光逐步熄灭 |
| 白天 `day` | `07:00-17:59` | 正常地图色彩、最高环境明度 |
| 黄昏 `dusk` | `18:00-19:59` | 暖橙侧光、阴影加深、灯光逐步开启 |
| 夜晚 `night` | `20:00-04:59` | 冷蓝环境光、月光与人工灯光成为视觉锚点 |

推荐新存档从第 1 天 `08:00` 开始，避免新玩家首次进入时处于低可见度夜晚。

### 4.3 推进与暂停

游戏时间仅在玩家可控制世界角色时推进。

暂停时间的状态：

- NPC 对话和剧情对话。
- 战斗场景。
- 背包、图鉴、卡组、任务等全屏菜单。
- 地图传送和加载。
- 浏览器标签页不可见或游戏失去运行焦点。

这样可以避免玩家阅读对白或整理卡组时错过 NPC、任务和时间窗口。

### 4.4 跨日

当 `minute_of_day >= 1440` 时：

```text
day_index += 1
minute_of_day -= 1440
```

跨日事件由统一事件触发，例如 `time:day-changed`。首版只负责广播，不立即加入每日经济、植物重生或复杂结算。

## 5. 状态模型与权威来源

### 5.1 数据结构

建议统一使用以下结构：

```ts
type TimePhase = 'dawn' | 'day' | 'dusk' | 'night'

interface GameTimeState {
  dayIndex: number
  minuteOfDay: number
  phase: TimePhase
  paused: boolean
}
```

`phase` 是根据 `minuteOfDay` 计算的派生值，不作为独立数据库字段保存，防止数据不一致。

### 5.2 权威边界

- 服务端存档是持久化权威：保存 `day_index`、`minute_of_day`。
- 客户端游戏状态是当前会话权威：只在可探索状态下推进时间。
- 客户端定期或在现有存档动作中提交最新时间。
- 服务端校验范围：`day_index >= 1`，`0 <= minute_of_day < 1440`。
- 服务器返回存档后，所有场景从同一状态读取时间，禁止直接读取设备时钟。

首版不根据退出时间补算离线时长，避免玩家离线后错过事件或被迫进入夜晚。

## 6. 场景表现

### 6.1 通用实现

世界场景增加一个覆盖镜头的环境色层，并根据当前分钟计算颜色与透明度。清晨和黄昏阶段进行连续插值，避免整点跳色。

环境层必须满足：

- 位于地图画面之上、UI 之下。
- 不参与碰撞和输入。
- 不对角色姓名、交互提示、小地图和任务 UI 进行染色。
- 夜间最低可见度仍能辨认道路、NPC 和可交互对象。
- 页面切到后台后停止动画与时间累积。

### 6.2 晨曦村

| 阶段 | 视觉表现 |
| --- | --- |
| 清晨 | 淡蓝环境光，东侧轻暖光，井边和屋顶保留薄雾 |
| 白天 | 保持现有暖色村庄主视觉，建筑和道路对比最清楚 |
| 黄昏 | 屋顶、道路边缘偏暖，树下和建筑背面阴影加深 |
| 夜晚 | 深蓝环境光，窗灯、旅店、杂货铺和中央广场提供暖色锚点 |

夜晚不能简单叠加高透明度黑色蒙层。优先使用冷色环境光加少量暖色局部灯，使角色与道路仍清晰可读。

### 6.3 微光森林

- 白天仍保持冷湿、幽深，不变成明亮翠绿森林。
- 黄昏强化剧情既定的“黄昏将尽”氛围。
- 夜晚提高月光空地、断月纹、银雾和菌群的局部可见度。
- 雾层透明度和粒子数量只做小幅变化，不能让夜晚成为视野惩罚。
- 核心剧情触发的光色优先级高于常规昼夜环境色。

### 6.4 战斗场景

`BattleScene` 必须读取统一的 `GameTimeState.phase`：

- 晨曦村：`dawn/day` 使用日间背景，`dusk/night` 使用夜间背景。
- 微光森林与其他区域首版可继续复用现有战斗背景，但环境色应与进入战斗时的阶段一致。
- 一场战斗期间锁定进入战斗时的阶段，不在战斗中途切换背景。
- 删除基于浏览器 `Date` 的昼夜判断。

## 7. UI 设计

HUD 显示一个紧凑时间组件：

```text
第 1 天  08:20  [太阳图标]
```

规则：

- 使用太阳、落日、月亮等熟悉图标，不显示长篇说明。
- 时间按 10 游戏分钟刷新显示，底层状态仍可逐分钟推进。
- 移动端只显示 `08:20 + 图标`，点击后再显示日期。
- 阶段切换时允许短暂淡入提示，如“夜幕降临”，但不得连续弹窗。
- 调试入口仅在开发环境显示，可设置日期、时间和倍率。

## 8. NPC 与玩法联动

### 8.1 NPC 作息

首版不做复杂移动日程，只支持配置可见或可交互时间：

```ts
interface NpcSchedule {
  availableFrom: number
  availableUntil: number
  unavailableLine?: string
  critical: boolean
}
```

建议规则：

- 杂货商：`08:00-20:00`。
- 铁匠：`07:00-19:00`。
- 训练教官：`06:00-22:00`。
- 村长、露娜、森林向导和主线任务 NPC：始终可交互，或在关闭时段提供剧情兜底。
- 普通 NPC 夜间可隐藏或更换静态位置，但首版不要求自动走回室内。

跨午夜时段必须支持，例如 `20:00-05:00`，判断逻辑不能假设开始时间小于结束时间。

### 8.2 任务与剧情

- 主线任务不得因时段条件形成永久阻塞。
- 若任务要求夜间调查，应提供等待点、明确目标或自动推进到可用时段；该能力不属于首版时，先不设置强制时间门槛。
- 剧情演出可临时覆盖环境光，但结束后必须恢复当前游戏时间对应的表现。
- 剧情不得直接修改玩家设备时间或依赖本地时区。

### 8.3 采集与战斗

首版只提供条件能力，不大规模新增限时内容：

- 可为少量植物配置 `available_phases`，未配置则全天可采集。
- 夜行怪物或夜间奖励属于后续内容。
- 进入战斗时记录 `phase_at_start`，服务端奖励逻辑如需使用时只能读取该稳定值。

## 9. 技术落点

预计涉及以下位置：

- `server/database/`
  - 新增追加式迁移，为玩家或存档增加 `day_index`、`minute_of_day`。
- `server/app/models.py`、`server/app/schemas.py`
  - 增加时间字段与输入校验。
- `server/app/api/save.py`
  - 存档加载与保存游戏时间。
- `game-client/src/api/types.ts`
  - 增加 `GameTimeState` 及存档响应字段。
- `game-client/src/stores/game.ts`
  - 维护统一时间状态、暂停原因与保存触发。
- `game-client/src/game/Game.ts`
  - 将当前时间写入 Phaser registry，供所有场景读取。
- `game-client/src/game/scenes/WorldScene.ts`
  - 推进时钟、更新环境光和地图特效。
- `game-client/src/game/scenes/BattleScene.ts`
  - 使用统一阶段选择背景，移除设备时间判断。
- `game-client/src/components/GameShell.vue`
  - 添加时间 HUD 和菜单暂停联动。

实现时应只有一个时间推进器。Vue、Pinia 和 Phaser 之间通过现有事件或 registry 同步，不能各自运行计时器。

## 10. 事件与派生函数

建议提供集中式纯函数：

```ts
getTimePhase(minuteOfDay): TimePhase
formatGameTime(minuteOfDay): string
isMinuteInRange(minuteOfDay, start, end): boolean
```

建议事件：

```text
time:minute-changed
time:phase-changed
time:day-changed
time:pause-changed
```

只有阶段变化和跨日需要驱动较重的场景更新。不要每秒重建全部地图对象或重新请求 NPC 数据。

## 11. 存档与异常恢复

- 新存档默认第 1 天 `08:00`。
- 旧存档缺少字段时按默认值兼容，不允许加载失败。
- 自动存档、手动存档、地图传送和页面退出前都应提交当前时间。
- 保存失败时客户端继续运行，并沿用现有错误提示策略；下一次保存重试。
- 服务端返回非法时间时客户端回退到默认值并记录可诊断错误，不渲染 `NaN` 时间。
- 同一次会话内只接受服务端确认的最新存档版本，避免旧响应覆盖新时间。

## 12. 对抗式审查

### Launch Blocker

| 风险 | 用户影响 | 上线要求 |
| --- | --- | --- |
| 继续读取设备真实时间 | 场景不一致，可通过改系统时间操控 | 所有玩法统一读取游戏内时钟 |
| 多个模块各自计时 | 世界、HUD、战斗和 NPC 时段漂移 | 只保留一个时间推进器 |
| 后台标签页继续累计 | 玩家回来后突然跨越数小时或多天 | 页面隐藏时暂停并丢弃隐藏时长 |
| 夜间蒙层过黑 | 道路、角色和交互目标不可见 | 夜晚可读性截图必须通过 |
| 关键 NPC 夜间关闭 | 主线或保存流程被阻断 | 关键 NPC 全天可用或提供兜底 |
| 跨午夜判断错误 | 夜间 NPC 永远不可用 | 单测覆盖 `20:00-05:00` |
| 旧存档无时间字段 | 老玩家无法进入游戏 | 数据库和客户端提供兼容默认值 |
| 战斗继续使用本机时钟 | 进入战斗后昼夜跳变 | 使用进入战斗时的统一阶段快照 |

### Follow-up

- 不同地图的夜间灯光资产数量不足。
- NPC 只隐藏、不走回室内，生活感有限。
- 时间倍率可能需要根据实机游玩节奏调整。
- 低性能设备的全屏色层与粒子需要进一步分档。

## 13. 实施顺序

1. 增加时间纯函数和单元测试，确定阶段边界与跨午夜规则。
2. 增加服务端存档字段、默认值和输入校验。
3. 在 Pinia 建立唯一时间状态和暂停原因集合。
4. 接入 HUD，验证推进、暂停、跨日和存档恢复。
5. 在 `WorldScene` 接入环境色层和阶段切换。
6. 修改 `BattleScene`，移除设备时间判断。
7. 接入首批 NPC 时段配置，并给关键 NPC 增加兜底。
8. 完成桌面、移动端、后台恢复、旧存档和战斗切换验证。

## 14. 验收标准

### 时间一致性

- [ ] 新存档从第 1 天 `08:00` 开始。
- [ ] 默认倍率下，现实 60 秒推进游戏 60 分钟，允许正常帧调度误差。
- [ ] 世界、HUD、NPC 和战斗读取同一时间阶段。
- [ ] 清晨、白天、黄昏、夜晚的边界分钟测试通过。
- [ ] `23:59 -> 次日 00:00` 正确增加日期。

### 暂停与恢复

- [ ] 对话、战斗、全屏菜单、加载和后台标签页期间时间不推进。
- [ ] 返回世界探索后从暂停点继续，不补算后台时间。
- [ ] 保存并重新登录后，日期和时间恢复一致。
- [ ] 旧存档能够以默认时间正常加载。

### 视觉与交互

- [ ] 晨曦村四个阶段可肉眼区分，过渡无明显闪烁。
- [ ] 夜晚仍能辨认道路、NPC、采集物、传送点和交互提示。
- [ ] 微光森林昼夜变化不破坏既定冷青黄昏视觉身份。
- [ ] 晨曦村战斗背景与进入战斗时的世界阶段一致。
- [ ] 关键 NPC 不会因夜间作息阻断主线任务。

### 工程验证

- [ ] 前端时间工具函数、暂停逻辑和 HUD 测试通过。
- [ ] 服务端存档默认值、合法范围、旧存档兼容和保存恢复测试通过。
- [ ] 前端 type-check、lint、build 通过。
- [ ] 桌面与移动端分别截取白天、黄昏、夜晚画面检查可读性。
- [ ] 浏览器切到后台至少 2 分钟后返回，游戏时间没有异常跳变。

## 15. 完成定义

首版昼夜系统的完成标准不是“画面能变暗”，而是：存在一份统一、可存档、可测试的游戏时间状态，世界探索、战斗、HUD 和 NPC 都以它为准，并且任何时段都不会破坏可读性或阻断核心流程。
