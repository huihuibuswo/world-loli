# 晨曦村布局与贴图优化方案

## 1. 优化目标

晨曦村应首先被识别为一个围绕公共生活形成的聚落，而不是散布在草地和树林中的独立建筑。优化后的第一视觉层级为：

1. 西北训练入口与主路。
2. 村长屋和晨曦井围合出的中央广场。
3. 铁匠铺、杂货铺和旅店组成的功能环。
4. 民居、菜圃和疗养小院组成的生活区。
5. 东南村口、森林向导和通往微光森林的道路。

本轮仅调整村庄布局语义和最必要的场景资产，不重做建筑、不增加室内地图，也不引入新的玩法系统。

## 2. 现状与根因

### 2.1 已确认事实

- 地图边界为 `0..2048 x 0..2048`。
- 主道路由 `WorldScene.drawWorld()` 绘制，从 `(32,150)` 经村庄中心延伸到东南传送点 `(1900,1840)`。
- 现有六栋建筑：村长屋、杂货铺、铁匠铺、旅店、两栋民居。
- 村长、杂货商和铁匠 NPC 已分别站在对应建筑门前。
- 露娜疗养位置在 `(1090,930)`，森林向导在 `(1160,1130)`，森林传送点在 `(1900,1840)`。
- 村内仍加载 `forest-stump`、`forest-obstacle` 和大量 `ancient-forest-tree`，其中部分位于核心活动区。
- 道路已有通往村长、铁匠、杂货铺、旅店和东南方向的支路，但缺少能解释路网汇聚原因的中心节点。

### 2.2 核心问题

1. **缺少聚落中心**：建筑围绕道路分散，却没有水井、广场或公告点形成公共空间。
2. **功能关系偏弱**：旅店、民居、疗养点和森林向导之间没有明显的生活区与出村区过渡。
3. **森林元素侵入村心**：树桩、障碍石和大尺寸古树遮挡道路与建筑，削弱村庄辨识度。
4. **生活设施缺失**：只有建筑，没有水井、篱笆、菜圃、货车等能说明居民日常活动的中小型物件。
5. **贴图语义重复**：独立障碍路牌 `(1030,1140)` 与真实传送点路牌的职责重叠，且森林树木数量超过村庄边界塑形所需。

## 3. 最小可靠方案

### 3.1 空间结构

保持现有西北至东南主路，不改变地图尺寸和森林传送点。将村庄核心收束到 `x=420..1260, y=360..1260`，形成“一心、两轴、四区”：

- **一心**：晨曦井中央广场，中心约 `(790,790)`。
- **两轴**：西北至东南主路；铁匠铺至杂货铺的东西向生活支路。
- **四区**：西北训练区、北侧行政区、西南生产区、东南生活与出村区。

```text
西北入口
    │  训练区
    ▼
  村长屋
     ╲
铁匠铺 ─ 晨曦井广场 ─ 杂货铺
     ╲       │          ╲
   民居A    旅店      疗养小院/民居B
               ╲          │
                 森林向导 ─ 村口路牌 ─ 微光森林
```

坐标表示碰撞脚印中心，沿用 `WorldScene.ts` 当前的定位机制。最终接入时应以截图和碰撞调试线做不超过 `40px` 的微调。

| 元素 | 当前坐标 | 建议坐标 | 尺寸 | 说明 |
|---|---:|---:|---:|---|
| 村长屋 | `(650,430)` | `(690,430)` | `420` | 保持北侧地标地位，正门朝向广场 |
| 铁匠铺 | `(300,750)` | `(390,760)` | `350` | 位于下风向和生产区，靠近西侧支路 |
| 杂货铺 | `(920,710)` | `(1110,720)` | `330` | 与铁匠铺夹住广场，面向客流主路 |
| 旅店 | `(760,1040)` | `(820,1110)` | `320` | 位于广场南侧，连接出村道路 |
| 民居 A | `(270,1080)` | `(430,1160)` | `280` | 归入西南生活区，与铁匠铺保持间距 |
| 民居 B | `(1080,950)` | `(1210,1030)` | `300` | 作为东侧疗养小院主体，服务露娜剧情 |

| 村口路牌 | 传送点显示 | `(1740,1660)` | `100` | 提前提示森林方向；传送点保留原提示表现 |

| 训练教官 | `(420,245)` | `(430,270)` | 与木偶间距约 `140px`，不挡主路 |
| 晨曦村村长 | `(650,545)` | `(690,575)` | 位于村长屋门前，玩家可从广场直达 |
| 铁匠少女苏娜 | `(300,850)` | `(390,875)` | 位于铁匠铺门前偏右，远离炉台碰撞区 |

### 3.4 道路调整

保留现有主路首尾控制点，替换村庄核心段，使道路围绕广场自然分叉：

```text
主路建议控制点：
(32,150) -> (320,210) -> (520,430) -> (690,620)
-> (790,790) -> (980,920) -> (1220,1120)
-> (1510,1450) -> (1740,1660) -> (1900,1840) -> (2048,1840)

支路：
广场 -> 村长屋门前 `(690,575)`
广场 -> 铁匠铺门前 `(390,875)`
广场 -> 杂货铺门前 `(1110,825)`
广场 -> 旅店门前 `(820,1210)`
旅店支路 -> 民居 A `(430,1260)`
东南支路 -> 疗养小院 `(1240,1130)`
```

道路视觉宽度可沿用当前半径 `58px`。中央广场额外叠加半径 `150..180px` 的泥土或石土混合地面，避免多条圆形道路叠加后出现不规则毛边。

## 4. 贴图增删方案

### 4.1 必须新增

只新增三个高复用资产，足以建立村庄中心、边界和生活感。

| 资源键 | 建议文件 | 用途 | 画布/显示尺寸 | 碰撞建议 |
|---|---|---|---|---|
| `village-well` | `village-well.png` | 中央广场地标 | `512 x 512` / `150 x 150` | 圆形，半径 `42px`，落在井台底部 |
| `village-fence-segment` | `village-fence-segment.png` | 菜圃、疗养小院边界 | `512 x 256` / `120 x 60` | 矩形，仅覆盖木栏底座；本轮放置于 `(1410,970)`、`(1410,1140)` |
| `village-cart-supplies` | `village-cart-supplies.png` | 杂货铺货运与生活场景 | `512 x 512` / `150 x 150` | 矩形，约 `100 x 42px` |

统一生成规格：

- 2D 手绘奇幻 RPG 场景物件，三分之四俯视视角。
- 木材、浅色石材、苔绿或麦黄色点缀，匹配现有建筑的暖色轮廓和清晰描边。
- 主体完整居中，四周保留至少 `10%` 透明留白。
- 无文字、无人物、无地面大投影、无环境背景、无水印。
- 最终 PNG 必须带透明通道；缩放到游戏显示尺寸后轮廓仍清晰。

建议生成提示词：

```text
Use case: stylized-concept
Asset type: transparent 2D game environment prop for a cozy fantasy village
Primary request: [晨曦井 / 矮木篱笆段 / 装有补给木箱的村庄板车]
Style/medium: polished hand-painted fantasy RPG sprite, three-quarter top-down view,
matching warm wooden cottages with moss-green roofs, clean readable silhouette,
soft warm highlights and restrained dark outline
Composition/framing: one complete isolated object centered with generous padding
Constraints: no character, no text, no watermark, no scenery, no floor plane,
no cast shadow beyond a very small contact shadow, transparent-background production asset
```

### 4.2 优先复用

- `village-signpost.png`：用于东南村口预告方向；传送点仍可复用同一资源。
- `village-cottage-b.png`：作为疗养小院主体，不新增专用“医院”建筑。
- `village-general-store.png` 自带蔬果、木桶和麻袋，不额外生成零散摊位贴图。
- `grass-ground.webp` 与 `dirt-path.webp`：继续作为地面和道路基础。
- 现有植物 cutout：用晨露草、蜜糖莓和阳铃花装饰菜圃周边，但采集节点与纯装饰物必须区分。

### 4.3 删除或移出村庄核心

| 元素 | 处理 | 原因 |
|---|---|---|
| `(1180,620)` 与 `(1050,520)` 的 `forest-obstacle` | 从 village 布局删除 | 无明确村庄语义，影响商店和广场可达性 |
| `(1160,300)` 与 `(1270,350)` 的 `forest-stump` | 从 village 布局删除 | 属于森林语汇，放在村内显得荒废 |
| `(1030,1140)` 的独立碰撞路牌 | 删除或移至 `(1740,1660)` | 与传送点路牌重复，当前还挤占生活区 |
| `(1260,820)`、`(520,1260)`、`(1050,1450)` 的大型古树 | 移至地图边缘 | 树冠遮挡核心建筑、NPC 和采集物 |
| 其余古树 | 保留约 7 棵形成外围林带 | 维持村庄位于森林边缘的世界观 |

建议外围古树坐标：`(1400,330)`、`(1760,620)`、`(1900,1030)`、`(1840,1510)`、`(1500,1870)`、`(950,1880)`、`(240,1580)`。树间应留出东南主路缺口，不能形成视觉封路。

## 6. 实施影响范围

后续落地预计涉及：

- `game-client/src/game/scenes/WorldScene.ts`
  - 拆分 village 与 forest 的障碍布局。
  - 更新建筑、树木、道路和公共设施坐标。
  - 为广场地面增加独立遮罩或绘制逻辑。
- `game-client/src/game/scenes/PreloadScene.ts`
  - 加载三张新增村庄设施贴图。
- `game-client/public/assets/generated/sprites/`
  - 新增井、篱笆、板车 PNG。
- 新数据库迁移（不得回改已发布迁移）
  - 更新晨曦村 NPC、露娜、采集物和村口引导位置。
- TypeScript 源文件为权威实现；仓库中的同名 `.js` 产物应由项目既有构建流程生成，不手工双改。

## 7. 推荐实施顺序

1. 先在 `WorldScene.ts` 中将 village/forest 布局数据分离，删除村内森林障碍。
2. 接入新建筑坐标与新道路控制点，暂用几何占位验证动线。
3. 新增并加载晨曦井、篱笆、板车贴图，校准透明边界和碰撞体。
4. 新建数据库迁移，同步 NPC、露娜和采集节点位置。
5. 在村庄四周恢复精简后的外围古树，检查不遮挡道路和交互对象。
6. 完成桌面与移动视口截图、碰撞巡检、剧情流程和构建验证。

## 8. 验收标准

### 8.1 视觉与村落感

- 首次进入后，一个视口内能识别村长屋、中央广场及至少两条支路。
- 六栋建筑围绕公共中心形成前后层级，不再沿地图边缘平均散布。
- 村内不出现孤立森林树桩或无语义障碍石。
- 古树主要形成外围轮廓，不遮挡建筑入口、NPC、采集物名称或传送点标签。
- 新增三张贴图与现有建筑的视角、描边、材质和光照方向一致。

### 8.2 动线与碰撞

- 玩家可从西北出生区域无阻挡抵达村长、训练区、铁匠、杂货铺、旅店、露娜和森林传送点。
- 每个交互 NPC 周围至少保留一个方向 `72px` 以上的站立净空。
- 建筑碰撞只覆盖可见底座，不覆盖透明留白、台阶前方或主要道路。
- 井、篱笆和板车不会形成死角；任何封闭装饰区域均留至少 `96px` 出入口。
- 玩家和巡游 NPC 不会出生在静态碰撞体内部。

### 8.3 剧情与数据一致性

- 开场剧情仍能引导玩家与村长交谈。
- 露娜完成开场剧情后出现在疗养小院且可交互。
- 森林向导位于出村道路附近，玩家能清晰发现。
- 五个村庄采集节点可见、可达，并与 habitat 文案一致。
- 往返微光森林的传送点 ID、目标地图和出生逻辑不变。

### 8.4 工程验证

- `npm run type-check`
- `npm run lint`
- `npm run build`
- 运行服务器地图/API 测试和数据库 schema 校验。
- 开启 Arcade Physics 调试体，逐个核对建筑与设施碰撞。
- 至少生成桌面和移动端各一张全村巡检截图；重点检查中央广场、疗养小院和东南村口。

## 9. 延后项

以下内容不属于本轮最小方案：昼夜灯光、烟囱粒子、动态水井、可交互门、室内地图、更多民居、农田系统、装饰随机化和环境音分区。只有在基础布局通过可达性与剧情验收后再评估。
