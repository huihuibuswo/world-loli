# 微光森林贴图、碰撞体与五区域布局修订方案 V2.0

> 状态：已实施（核心修订与运行态验收完成，目标设备复核项保留）
>
> 日期：2026-07-31
>
> 适用范围：微光森林部分1至部分5的运行时贴图、碰撞体、路径、地标、前后景和传送安全区
>
> 本文替代 V1 文档中“贴图加工、碰撞和五区域运行时截图已经通过”的相关验收结论；原剧情事实、地图命名和相邻传送关系继续有效。

## 1. 修订结论

当前问题不是单纯的坐标微调，而是资产加工、碰撞建模和地图布局三个环节同时失真：

1. 多个图集按固定网格切片，但原图中的单体并未严格落在网格内，导致一张运行时贴图包含多个残片、邻格碎片或半个对象。
2. 加工脚本把所有切片重新居中到统一透明画布，丢失了单体真实脚点和底部锚点；运行时再用手填 offset 猜测碰撞位置。
3. 同类资产共用一套碰撞体，但同一图集内对象的轮廓、宽度、朝向和脚点差异很大。
4. 局部水面、庭院和雾汇盆地使用不透明 RGB 大图直接叠在地表上，必然出现矩形背景、硬边和层间色差。
5. 地表虽然做到了首尾像素相等，但大尺度亮斑和构图每 512px 重复一次，仍会形成肉眼可见的棋盘重复。
6. 当前区域布局主要是把贴图散点摆入地图，没有先定义可通行空间、边界阻挡、地标净空和视觉层级，因此出现贴图交错、路径穿模、碰撞与画面不一致。

本轮必须采用以下最小可靠方案：

- 新建版本化资产集 `glimmer-forest-regions-v2`，保留 V1 作为回滚基线。
- 重新切分图集，输出单对象、紧画布、稳定脚点的透明贴图。
- 视觉摆放与物理碰撞分离；碰撞体不再从贴图画布和通用 offset 推导。
- 局部地表改为透明软边贴花或路径遮罩，不再使用不透明矩形覆盖。
- 五个区域按本文给出的 V2 路线、边界、地标和安全区重新布局。

## 3. 事实、假设与不变量

### 3.1 已确认事实

- `save_chroma_grid()` 使用固定行列网格裁切 W03、W05、R03、N03、N06。
- D03 使用五个手写百分比矩形裁切，多个矩形覆盖到相邻树木或残片。
- `fit_canvas()` 会裁掉透明边缘后，把结果重新居中到固定画布，而 manifest 不记录真实 Alpha 边界、脚点和碰撞建议。
- 当前 manifest 校验只检查尺寸、四角 Alpha 和镜像哈希；即使一张贴图含多个对象残片，仍会判定通过。
- `forestRegions.ts` 对部分2的十个溪岸组件使用同一碰撞体，对部分3的不同遗迹只按序号分两套碰撞，对部分5五棵不同朝向古木使用同一碰撞体。
- `WorldScene.ts` 使用 Arcade Physics 的轴对齐静态体；贴图可旋转，但除 90 度外碰撞体不会随视觉角度旋转。
- R05 下沉庭院、D04 雾汇盆地和 W02 水面是 RGB 不透明图片，却被作为局部覆盖层放到另一张地表上。
- 当前自动测试只验证区域键存在和文件存在，不验证布局、碰撞、Alpha 轮廓、接缝或传送净空。

### 3.2 不允许破坏的不变量

- 五张地图仍使用 `glimmer_forest_part_1` 至 `glimmer_forest_part_5`。
- 部分1数据库精确名称仍为 `微光森林`。
- 相邻连通关系仍为：晨曦村 ↔ 部分1 ↔ 部分2 ↔ 部分3 ↔ 部分4 ↔ 部分5。
- 部分1已有 NPC、植物、证据和剧情对象坐标保持不变；只能调整其周围环境布局和碰撞。
- 每张地图继续使用独立 `2048 x 2048` 坐标系。
- 不新增任务、NPC、掉落、战斗或剧情状态。

### 4.1 图集切片错乱

| N03 荧光路径标志 | `4 x 4` 固定网格 | 部分输出带相邻叶片或枝条残片；不同对象占画布比例差异过大 | 单体提取并统一脚点，不强制统一正方形画布 |
| N06 伪路径标志 | `4 x 4` 固定网格 | 多个输出包含跨格石板、枝条和植物碎片 | 重新分离；首版只保留轮廓完整的 6 至 8 个对象 |

### 4.2 Alpha 画布与锚点异常

像素审计显示：

| 资产 | 原画布 | 实际可见宽度 | 当前风险 |
| --- | ---: | ---: | --- |
| P2 `stream-bank-01` | 384 | 48.7% | 统一 180px 碰撞明显宽于可见主体 |
| P2 `stream-bank-05` | 384 | 39.6% | 同一碰撞模板会产生大面积透明阻挡 |
| P4 `tree-corridor-left` | 1024 | 37.9% | 贴图被压缩后视觉主体过窄，碰撞仍覆盖大宽度 |
| P4 `tree-corridor-right` | 1024 | 32.1% | 左右空白超过画布三分之二 |
| P5 `broken-canopy-tree-wall-01` | 1024 | 31.7% | 边界树墙表现为孤立树柱，无法自然拼接 |
| P5 `inward-leaning-tree-02` | 640x768 | 可见高度 68.0% | 与其他四棵树使用同一脚点和碰撞会漂移 |

V2 输出规则：

- 单体贴图画布只保留 `8px` 至 `16px` 安全边距。
- 每张贴图必须记录 `alpha_bbox`、`anchor`、`footpoint`、`visual_size` 和允许的碰撞角色。
- 树、柱、路牌默认使用底部中心脚点；横向墙体使用底边中心；地表贴花使用中心锚点。
- 禁止为了统一尺寸把窄树强行放入 1024px 宽画布。
- 同一图集拆出的对象可以尺寸不同，不要求全部输出为相同正方形。

### 4.3 背景和接缝异常

| 资产 | 当前问题 | V2 修改 |
| --- | --- | --- |
| P2 地表 | 边缘像素相等，但中心蓝色亮斑每 512px 重复 | 输出 3 个同色相地表变体；运行时以 1024px 宏观噪声贴花打散重复 |
| P2 水面 | RGB 不透明矩形旋转后覆盖地表，边角和色差必然可见 | 输出透明水面遮罩、两侧浅滩贴花和独立水流高光；水域形状由路径带决定 |
| P3 地表 | 四角冷白亮斑形成明显周期图案 | 降低大尺度定向亮斑；补 2 个随机旋转不可见的变体 |
| P3 下沉庭院 | 1024 RGB 方图，左右/上下边缘差分别约 26.76/34.57 | 改为 RGBA 软边地表贴花；四周至少 96px 羽化，禁止作为 tileSprite |
| P4 地表 | 高频纹理一致，但 512px 重复仍可辨认 | 加入低频暗部宏观覆盖层，不在基础 tile 内烘焙强地标 |
| P5 地表 | 石块纹理重复方向统一 | 增加旋转不可见的第二变体或宏观遮罩 |
| P5 雾汇盆地 | RGB 方图带灰色背景，作为局部叠层会出现方形底板 | 分成透明盆地边缘、中心雾面和响应特效三层 |

### 4.4 发光和抠图边缘

- W06、W07、N04、D06 多数半透明像素仍保留大量黑/白底色信息；在 `ADD` 混合下会放大灰白边缘。
- V2 特效必须使用预乘 Alpha 友好的颜色清理：透明度越低，RGB 越接近目标银蓝色，而不是原黑底或纯白。
- 特效验收不能只检查四角透明；必须在深绿、灰蓝和纯黑三种底色上预览边缘。

## 5. 碰撞体问题审计

### 5.1 当前碰撞与可见像素重合率

以下比例表示当前碰撞矩形中实际覆盖到非透明像素的面积。比例过低意味着玩家会撞到透明区域；它不是碰撞质量的唯一指标，但足以证明通用模板失效。

| 资产 | 当前重合率 | 结论 |
| --- | ---: | --- |
| P2 溪岸 03 / 08 / 09 | 15.2% / 19.4% / 16.5% | 透明阻挡严重，且溪岸本身不应全部作为实体障碍 |
| P3 遗迹 05 / 09 / 10 | 25.4% / 23.8% / 25.9% | 台阶、矮墙、拱门不能共用同一矩形 |
| P4 左树廊 | 13.4% | 碰撞宽度远大于实际树干 |
| P5 树墙 01 / 02 | 26.7% / 17.8% | 树墙视觉与物理边界不一致 |
| P5 向心古木 01 / 03 / 04 / 05 | 0.2% / 0% / 0.5% / 0.3% | 当前碰撞几乎完全落在树木透明区 |

### 5.2 根因

1. `body.offsetX/offsetY` 是对统一显示画布的人工猜测，不来源于加工后的 Alpha bbox。
2. 不同语义对象按数组序号套用同一模板。
3. 视觉旋转与 Arcade 轴对齐碰撞混用；`±24°` 的溪岸贴图旋转后碰撞仍为水平矩形。
4. 溪岸、水面边缘、前景枝叶等装饰被错误归入 `obstacles`。
5. 树墙需要连续边界碰撞带，但当前实现让每张稀疏树柱各自承担大矩形碰撞。

### 5.3 V2 碰撞原则

- 视觉贴图和物理碰撞拆成两张表：`props` 只负责绘制，`colliders` 只负责通行边界。
- 溪岸、浅滩、水面高光、前景枝叶默认无碰撞。
- 河流不可通行边界使用沿水域两侧布置的短矩形/圆形碰撞链，不从溪岸贴图反推。
- 树木碰撞只覆盖树干与最粗主根；树冠和倾斜枝条不碰撞。
- 墙体、遗迹和树墙可用多个短矩形组合，不用一张大矩形包住透明空洞。
- 需要斜向碰撞时，首选 3 至 5 个短轴对齐矩形形成阶梯链；不依赖旋转后的 Arcade Body。
- 每个碰撞体必须有 `id` 和调试标签，开发模式支持显示轮廓。

### 5.4 建议数据结构

```ts
type ForestProp = {
  id: string
  texture: string
  x: number
  y: number
  width: number
  height: number
  origin?: { x: number; y: number }
  angle?: number
  depthRole: 'ground-decal' | 'underlay' | 'world' | 'canopy' | 'foreground' | 'effect'
}

type ForestCollider = {
  id: string
  shape: 'rect' | 'circle'
  x: number
  y: number
  width?: number
  height?: number
  radius?: number
  role: 'boundary' | 'trunk' | 'ruin' | 'water' | 'landmark'
}
```

不在 V2 引入多边形物理或新物理引擎；短矩形链已经足以解决当前问题。

## 6. 五区域通用布局契约

### 6.1 通行与安全尺寸

| 项目 | 最小要求 |
| --- | ---: |
| 主路有效宽度 | 240px |
| 支路有效宽度 | 180px |
| 传送点净空 | 以传送点为中心至少 240x240px |
| 出生点净空 | 以出生点为中心至少 220x220px |
| 地标交互净空 | 至少 260x220px |
| 战斗/剧情演出净空 | 至少 520x420px |
| 障碍与地图边缘安全距离 | 可见主体不得被裁掉，脚点至少离边缘 48px |

### 6.2 分层顺序

```text
L0 基础地表
L1 路径、水域和软边地表贴花
L2 无碰撞小型装饰
L3 桥面下层、地面根系、矮遗迹
L4 玩家、NPC、植物、证据、传送点和世界障碍
L5 树冠、拱门上沿、桥面上沿
L6 低位雾和局部响应特效
L7 可淡出的前景枝叶
```

- 桥、拱门、大树必须拆成下层与上层，禁止一张贴图同时压住玩家脚部和头部。
- `depth = y` 只适用于脚点明确的世界对象；地表贴花、全景特效和前景不能直接套用对象中心 y。
- 前景枝叶进入玩家 180px 范围时降至 35% 至 45% Alpha。

### 6.3 路径与碰撞先后顺序

每张地图必须按以下顺序制作：

1. 先画主路中心线和传送安全区。
2. 再定义不可通行边界碰撞带。
3. 用自动检查确认主路连续且不穿碰撞。
4. 再摆放地标、树、遗迹和装饰贴图。
5. 最后添加雾、前景和发光效果。

禁止先把贴图铺满画面，再从剩余空隙中寻找道路。

### 6.4 跨区域传送贴图布局

传送贴图跟随数据库门户对象生成，不写入区域装饰散点数组。视觉中心必须朝向地图边缘，触发区、出生点和标签分别建模。

| 区域 | 入口贴图与中心 | 出口贴图与中心 | 安全要求 |
| --- | --- | --- | --- |
| 部分1 | `forest-entry-marker-left`：`(1900,1840)`，返回晨曦村 | `forest-region-exit-right`：`(1880,260)`，前往部分2 | 两端 240x240px 内无树冠、碰撞和剧情对象 |
| 部分2 | `forest-region-exit-left`：`(160,1840)`，返回部分1 | `forest-region-exit-right`：`(1880,260)`，前往部分3 | 入口到 `(280,1700)` 出生点直接可走；出口避开雾瀑主体 |
| 部分3 | `forest-region-exit-left`：`(160,1840)`，返回部分2 | `forest-region-exit-right`：`(1880,260)`，前往部分4 | 出口根门只作界标，不能压住触发区 |
| 部分4 | `forest-region-exit-left`：`(160,1840)`，返回部分3 | `forest-region-exit-right`：`(1880,260)`，前往部分5 | 前景枝叶和夜萤不得覆盖标签 |
| 部分5 | `forest-region-exit-left`：`(160,1840)`，返回部分4 | 无后续区域出口 | 入口连接外环与核心，不得被树墙封闭 |

传送触发区建议为 112x112px 至 144x144px，必须小于视觉净空；目标出生点与反向触发区中心至少相距 140px，避免切图后立即回传。地图切换遮罩属于全屏 UI 层，不得被地图前景贴图裁切或遮挡。

## 12. V2 资产加工规范

### 12.1 目录与回滚

```text
game-client/art-source/generated/glimmer-forest-regions-v2/
game-client/public/assets/generated/environment/glimmer-forest/regions-v2/
game-client/scripts/prepare_glimmer_forest_regions_v2_assets.py
```

- 客户端通过单一根路径切换 V1/V2，回滚时不修改数据库。

### 12.2 图集提取流程

1. 去除洋红背景并清理溢色。
2. 对 Alpha 掩码做连通域分析。
3. 过滤小于主体面积 0.15% 的孤立噪点。
4. 合并属于同一对象且间距小于阈值的组件。
5. 生成候选 bbox 总览，由人工确认语义映射。
6. 按确认后的 bbox 输出紧画布资产。
7. 写入脚点、Alpha bbox 和建议视觉尺寸。

固定网格只能用于对象严格对齐、预览确认无跨格内容的图集；W03、R03、N03、N06、D03 禁止继续使用固定网格。

### 12.3 Manifest 新增字段

```json
{
  "name": "inward-leaning-tree-01.png",
  "width": 522,
  "height": 593,
  "alpha_bbox": [0, 0, 522, 593],
  "anchor": [0.5, 1.0],
  "footpoint": [261, 572],
  "role": "world-tree",
  "collision_profile": "tree-01-trunk",
  "component_count": 1,
  "review": "approved"
}
```

### 12.4 自动拒绝条件

- 单体资产出现非预期的第二个大连通域。
- Alpha bbox 占画布宽或高低于 70%，且没有 `intentional_padding` 说明。
- 局部地表贴花为 RGB/不透明模式。
- 碰撞模板引用未审核脚点。
- 地表边缘虽相等但 2x2 预览出现明显中心亮斑重复。
- 黑底、白边、洋红边或棋盘格伪透明。

## 13. 运行时配置重组

`ForestRegionConfig` 最少拆为：

```text
groundLayers   基础地表与宏观遮罩
paths          主路/支路中心线及宽度
props          无物理语义的视觉对象
colliders      独立物理边界
landmarks      需要分层或交互净空的地标
effects        雾、粒子、响应特效
foreground     可淡出的前景对象
safeZones      出生点、传送点、交互和演出净空
```

布局验证在创建 Phaser 对象前运行；检测失败时开发环境直接抛出可读错误，不静默加载错误地图。

## 15. 对抗式审查

### Launch Blocker

| 问题 | 用户影响 | 上线要求 |
| --- | --- | --- |
| 单张贴图含多个残片 | 画面交错、漂浮碎片、错误遮挡 | 所有运行时单体通过连通域和人工总览检查 |
| 碰撞落在透明区 | 玩家被空气墙卡住 | 树、遗迹和边界逐类完成调试层截图 |
| 明显实体无碰撞 | 玩家穿树、穿墙、穿地标 | 可见实体脚部与碰撞误差不超过约 12px 至 20px |
| RGB 局部覆盖层 | 地图出现方形底板和色差 | 局部覆盖全部改为 RGBA 软边或路径遮罩 |
| 主路穿过碰撞链 | 地图不可通行或需要绕透明空隙 | 自动采样主路净宽并手动走完全程 |
| 出生点/传送点压碰撞 | 玩家切图后被困或反复触发 | 每端 220px 以上安全净空通过 |
| 前景不淡出 | 角色、出口和标签被长期遮住 | 玩家邻域前景自动降透明 |

### Follow-up

- 地表变体不足仍可能产生低频重复。
- 部分区域小型装饰密度需要在移动端继续减量。
- Arcade 矩形链在斜线边界上仍有轻微阶梯感。
- 发光边缘在 HDR 或高亮屏幕上的表现需要目标设备复核。
