# 微光森林多区域总体设计 V1.0

> 文档状态：五区域运行时首版  
> 当前实现：部分1至部分5均已接入独立地图、资产与相邻双向传送  
> 上游规范：`微光森林地图与内部贴图优化规范_V1.0.md`  
> 适用范围：微光森林区域拆分、跨区连接、区域职责与后续制作边界  
> 本文记录首版运行时契约；部分1数据库精确名称与既有剧情事实保持不变

## 1. 设计结论

当前游戏中的 `2048 x 2048` 微光森林地图不再代表整座微光森林，正式定义为：

> **微光森林·部分1：月痕前庭**

它是晨曦村一侧最容易抵达的森林边缘与开局异常调查区，承载森林向导、三处证据、露娜初遇、月光空地和月痕古树等现有内容。

完整微光森林由 5 个可独立加载、独立制作和独立验收的地图部分组成：

1. 部分1：月痕前庭。
2. 部分2：银雾溪谷。
3. 部分3：盘根遗迹。
4. 部分4：夜萤幽径。
5. 部分5：断月深林。

各部分共享冷青、深绿、银蓝微光和逆流雾的森林视觉身份，但必须拥有不同的地形结构、导航方式、玩法职责和地标，不能只是更换装饰物的五张同类地图。

## 2. 目标与非目标

### 2.1 目标

- 明确当前地图只是整个微光森林的部分1。
- 建立完整森林的区域层级、相对位置和出入口关系。
- 为每个部分定义唯一的视觉主题、核心玩法、叙事职责和资源生态。
- 保留现有开局剧情、坐标、地图传送和植物采集能力。
- 让后续区域可以逐张制作、逐张上线，不要求一次完成整座森林。

### 2.2 非目标

- 本文不编写部分2至部分5的完整任务线、敌人卡组或对白。
- 不提前解释断月纹、逆流雾或幕后异常的最终真相。
- 不把五个部分合成一张超大无缝地图。
- 不在本轮新增部分2至部分5的任务、NPC、掉落、战斗或剧情解锁状态。
- 不重做部分1；其内部布局继续以现有优化规范和实现为准。

## 3. 设计原则

### 3.1 一部分一个主要问题

每张地图只突出一个主要探索问题：

| 部分 | 玩家首先要解决的问题 |
| --- | --- |
| 部分1 月痕前庭 | 森林发生了什么异常？ |
| 部分2 银雾溪谷 | 雾为什么逆着水流移动？ |
| 部分3 盘根遗迹 | 旧遗迹为何被根系主动封闭？ |
| 部分4 夜萤幽径 | 在方向感失效时如何辨认真实路径？ |
| 部分5 断月深林 | 多处异常最终指向哪里？ |

### 3.2 地图独立加载

- 每个部分对应一条独立 `map_data` 记录和独立本地坐标系。
- 单图建议继续控制在约 `2048 x 2048`，根据玩法可在 `1536 x 1536` 至 `2560 x 2560` 内调整。
- 区域切换复用现有 `map_portal -> target_map_id -> spawn_x/spawn_y` 机制。
- 跨区后只加载当前区域的地图对象、碰撞、环境特效和音乐，不让所有森林资产常驻内存。

### 3.3 视觉同源但轮廓不同

全森林保持以下共同元素：

- 冷湿地表、深色树干和低饱和植被。
- 冷白或银蓝微光，不使用暖金主光。
- 神秘、压迫但不血腥恐怖。
- 逆流雾与断月异常只在关键位置增强。

每部分必须至少有一个远看即可识别的独立轮廓：溪谷水面、巨型盘根、夜萤树廊或断裂树冠天幕，不能只依靠环境滤镜区分。

## 6. 部分1：月痕前庭

### 6.1 现状定义

当前数据库地图名 `微光森林`、`map_type = forest`、约 `2048 x 2048` 的地图正式视为部分1。

为保持兼容，首轮只改变设计称谓，不立即重命名数据库记录。现有服务端剧情逻辑使用精确地图名 `微光森林`，直接改名会破坏开局校验。

建议后续界面显示：

```text
微光森林·月痕前庭
```

建议稳定区域标识：

```text
glimmer_forest_part_1
```

### 6.2 已有内容归属

以下内容全部属于部分1，不需要迁移到其他地图：

- 东南入口与返回晨曦村的出口。
- 森林向导和训练教官。
- 银叶草、星砂薄荷、月光百合、雾绒蕨、梦露花的首批节点。
- 异常闭合的月光植物、突然中断的狼族足迹、断月雾核三处证据。
- 露娜初遇、首次战斗与月光空地。
- 当前唯一月痕古树、残缺断月刻痕和两层逆流雾。

### 6.3 地位调整

现有规范中的“核心古树”继续是部分1的视觉核心，但不再表述为整座微光森林的最终中心。它是靠近人类活动边界的一株月痕古树，也是玩家第一次看到异常汇聚的地方。

### 6.4 当前出口

- 东南侧保留返回晨曦村的出口。
- 北侧或东北侧连接部分2“银雾溪谷”。
- 首版不增加剧情门槛，两个出口均由服务端门户数据授权。

## 7. 部分2：银雾溪谷

### 7.1 一句话体验

玩家沿部分1的逆流雾进入低洼溪谷，发现银雾逆着真实水流爬升，并通过浅滩、倒木和雾向判断安全路线。

### 7.2 区域特征

- 视觉地标：弯曲溪流、层叠浅滩、贴水逆流雾和一处低矮雾瀑。
- 主色差异：冷灰蓝水面高于部分1占比，植被更湿、更低矮。
- 路径结构：沿溪主路加两条跨水支路，不做复杂跳跃平台。
- 核心玩法：观察水流与雾流的相反方向，选择可通行浅滩。
- 采集倾向：星砂薄荷、雾绒蕨及新的水边普通材料。
- 风险类型：湿地减速区、被雾暂时遮蔽的巡游敌人、错误浅滩绕行。

### 7.3 叙事边界

本区只证明逆流雾会跨越地形并主动向深处移动，不解释其来源。可以留下被侵蚀的测水桩、向导旧标记和突然上游的漂浮物，不能直接出现幕后角色说明书。

### 7.4 出入口

- 南部入口连接部分1。
- 北部出口连接部分3。
- 首版不设置跨区捷径。

## 8. 部分3：盘根遗迹

### 8.1 一句话体验

玩家进入被巨型根系包裹的旧遗迹，在不破坏古树生态的前提下调整通路，寻找断月异常出现前就存在的历史痕迹。

### 8.2 区域特征

- 视觉地标：跨越画面的巨根拱门、下沉石庭和被树根抬起的断墙。
- 主色差异：灰青石材与深褐根系占比提高，银蓝微光更少、更集中。
- 路径结构：一个中心庭院连接三段环路，开路后形成短回环。
- 核心玩法：调查根系生长方向、解除软封锁、从遗迹高低层寻找回路。
- 采集倾向：梦露花、根部菌群、遗迹附近的稀有材料。
- 风险类型：视觉上可见但暂时不可达的区域、根系闭合、狭窄处战斗。

### 8.3 遗迹表达规则

- 遗迹纹样必须与断月纹区分，不能暗示二者已经确认同源。
- 不使用墓地、献祭台、现代文字或完整法阵。
- 解谜只改变局部通路，不做全图重置或长距离搬箱。
- 任何根系开路状态必须可保存，重新进入地图后不能恢复为封路状态。

### 8.4 出入口

- 南部入口连接部分2。
- 北部出口连接部分4。
- 首版不设置跨区捷径。

## 9. 部分4：夜萤幽径

### 9.1 一句话体验

森林树冠在此遮蔽天空，玩家不能依靠道路颜色前进，只能通过夜萤群、树皮反光、声音和雾的间歇变化辨认真实路径。

### 9.2 区域特征

- 视觉地标：高密树廊、成带夜萤、交错树影和远处断裂林冠。
- 主色差异：全森林最暗，但交互物和可通行路径保持清晰冷光轮廓。
- 路径结构：短岔路组成的压缩迷路体验，每个错误分支应在 20 至 40 秒内回到主环。
- 核心玩法：环境导航，不依赖固定箭头或连续路牌。
- 采集倾向：夜间强化的月光百合、稀有菌群和少量梦露花。
- 风险类型：巡游敌人、短时灭灯、伪路径和视野压缩。

### 9.3 昼夜规则

- 白天可进入，但仍保持树冠下的昏暗身份。
- 黄昏与夜晚增强夜萤和路线提示，不允许夜晚反而更难辨认主路。
- 关键导航不能只依赖动态粒子；开启 reduced-motion 后使用静态荧光附着点替代。
- 不设置必须等待现实时间或强制睡到夜晚才能通过的首版门槛。

### 9.4 出入口

- 南部入口连接部分3。
- 北部主出口连接部分5。
- 首版不新增支线解锁或多入口汇合状态。

## 10. 部分5：断月深林

### 10.1 一句话体验

玩家抵达多条逆流雾共同指向的深林盆地，把前四部分收集到的环境证据组合起来，完成当前森林篇章的阶段性调查与战斗。

### 10.2 区域特征

- 视觉地标：断裂树冠天幕、向中心倾斜的古木、雾汇盆地和不完整冷白月影。
- 主色差异：银蓝异常更强，但仍保留大面积深绿和灰黑实体，避免全图发光。
- 路径结构：外环调查点加中央演出区，先观察再进入核心净空。
- 核心玩法：综合使用雾向、足迹、植物反应和遗迹信息完成证据确认。
- 采集倾向：少量高价值节点，不能把章节高潮区做成资源农场。
- 风险类型：精英战斗、阶段环境变化、出口临时关闭和演出后恢复。

### 10.3 内容边界

- 本区可以收束“这次森林异常”，但不必揭示整个世界观的最终敌人。
- 不默认设置世界树、神殿、最终祭坛或不可逆地图毁灭。
- 中央地标不能复制部分1月痕古树的轮廓；部分1是首次异常见证，本区是多种异常汇合的空间。
- 章节演出结束后地图必须恢复可探索状态，并提供明确离开方式。

### 10.4 出入口

- 南部入口连接部分4。
- 未来若新增阶段目标，可评估稳定回程捷径；首版只保留与部分4相邻的双向门户。
- 进入关键演出前应有明确提示和安全存档点，但不使用不可恢复的永久锁区。

## 11. 跨区解锁与任务规则

### 11.1 最小解锁流程

```text
晨曦村
  -> 部分1
  -> 部分2
  -> 部分3
  -> 部分4
  -> 部分5
```

首版不新增解锁状态，区域连通由服务端相邻门户授权。未来若加入任务门槛，应另行定义服务端持久化状态与迁移。

### 11.2 防阻塞规则

- 以下规则适用于未来新增跨区任务或解锁状态，不属于首版探索地图数据：
- 主线钥匙、证据和开路状态必须保存在服务端。
- 玩家离开地图、战斗失败或重新登录后，不得丢失已开启出口。
- 任务道具不能只存在于客户端场景对象中。
- 部分5演出失败或断线后应能从最近稳定阶段恢复，不重复发放唯一奖励。

### 11.3 快速移动

首版不建设全局快速旅行系统或局部捷径，只使用相邻双向门户。后续捷径必须单独验收授权、出生点和存档恢复。

## 12. 地图数据与命名契约

### 12.1 兼容现状

当前部分1继续保留：

```text
map_name: 微光森林
map_type: forest
bounds: 2048 x 2048
```

原因：现有开局服务和测试使用 `微光森林` 精确匹配，本文不授权直接重命名。

### 12.2 当前区域字段

首版已在 `resource_json` 中持久化稳定区域信息，避免为显示身份立即扩表：

```json
{
  "region_key": "glimmer_forest_part_1",
  "region_name": "微光森林·部分1：月痕前庭"
}
```

五个部分使用以下独立 `map_name` 和稳定 `region_key`：

| 部分 | `map_name` | `region_key` |
| --- | --- | --- |
| P1 | 微光森林 | `glimmer_forest_part_1` |
| P2 | 微光森林·银雾溪谷 | `glimmer_forest_part_2` |
| P3 | 微光森林·盘根遗迹 | `glimmer_forest_part_3` |
| P4 | 微光森林·夜萤幽径 | `glimmer_forest_part_4` |
| P5 | 微光森林·断月深林 | `glimmer_forest_part_5` |

### 12.3 客户端选择规则

- `map_type = forest` 只表示森林大类，不能继续唯一决定路径、障碍和地标布局。
- 客户端场景按 `region_key` 选择区域配置；缺少或未知该字段时，`forest` 地图回退为部分1。
- 坐标只在当前地图内有效，禁止跨地图复用同一组绝对坐标表达同一个世界位置。
- 每个传送点必须同时定义目标地图和目标出生点，并在两端分别保留安全净空。


- 不覆盖 `glimmer-forest-v1` 的部分1资产。
- 每批资产保留 manifest、尺寸、来源、运行时路径和预览图。
- 大型透明特效必须提供 reduced-motion 或静态降级。
- 区域专属地标使用语义纹理键，禁止继续使用 `forest-object-1` 一类模糊命名。

## 14. 实施优先级

### Must

1. 在产品与设计语义中把当前地图固定为部分1“月痕前庭”。
2. 新增地图采用独立 `map_data`、`region_key` 和本地坐标系。
3. 保持部分1数据库地图名兼容，不直接破坏开局服务。
4. 五区域按 `region_key` 选择独立配置，并通过相邻双向传送形成完整闭环。
5. 每张新地图必须有独立地标、主玩法、往返出口和存档恢复验证。

### Should

- 在地图标题、小地图或进入提示中显示区域正式名称。
- 完成主节点后提供局部捷径，控制重复赶路。
- 为不同部分配置独立环境声和昼夜参数。
- 把部分1现有硬编码布局逐步收敛到区域配置中。

### Defer

- 全森林无缝大地图。
- 随机生成迷宫和程序化道路。
- 全局快速旅行网络。
- 部分2至部分5的新任务、NPC、掉落、战斗与剧情解锁。
- 最终世界观真相、终局首领和跨章节永久地形变化。

## 15. 对抗式审查

### Launch Blocker

| 风险 | 用户影响 | 上线要求 |
| --- | --- | --- |
| 直接重命名部分1数据库记录 | 开局剧情、传送或测试失效 | 保留 `微光森林`，先增加显示名与区域键 |
| 只按 `map_type = forest` 渲染 | 五个部分全部套用部分1路径和古树 | 新地图必须按稳定区域标识选择配置 |
| 出口单向或出生点压在碰撞体内 | 玩家被困、循环传送或无法移动 | 双端传送与出生净空手动验收 |
| 解锁状态只保存在客户端 | 刷新或换设备后出口重新锁定 | 服务端持久化关键进度 |
| 区域过暗或浓雾遮挡 | 玩家看不清道路、敌人和采集物 | 桌面与移动端可读性截图通过 |
| 部分2/3顺序写死 | 玩家选择另一条路线后主线阻塞 | 两种完成顺序都进入同一稳定阶段 |
| 部分5演出锁区后断线 | 玩家无法继续或重复领奖 | 阶段幂等、可恢复、奖励唯一 |

### Follow-up

- 区域间音乐过渡和环境声串音。
- 多地图资源预加载造成首进卡顿。
- 捷径过多削弱森林尺度感。
- 后续植物分布与现有赠礼经济的平衡。
- 部分4导航提示在色觉差异和 reduced-motion 下的可识别性。

## 16. 分区验收模板

每个新部分立项时至少满足：

### 内容

- [ ] 有一句话体验和唯一核心问题。
- [ ] 有一个不可与其他部分混淆的主地标。
- [ ] 有主路线、有限支路、入口、出口和回程方案。
- [ ] 不提前泄露未确认的世界观真相。

### 可玩性

- [ ] 玩家可从上一区域进入并安全出生。
- [ ] 玩家可完成主节点并返回，不存在永久锁死。
- [ ] 战斗、采集、证据和传送点不互相重叠。
- [ ] 昼夜与 reduced-motion 状态下主路径仍可辨认。

### 数据

- [ ] 地图拥有稳定 `region_key`。
- [ ] 传送点目标、出生点和双向关系正确。
- [ ] 解锁、机关和唯一奖励可保存且幂等。
- [ ] 重新登录、战斗失败和接口重试不会回退关键进度。

### 工程与资产

- [ ] 客户端按区域标识加载正确布局和资产。
- [ ] 区域专属资产位于独立版本目录并有 manifest。
- [ ] type-check、build 和相关服务端测试通过。
- [ ] 桌面与移动端完成入口、主节点、出口和最暗时段截图检查。

## 17. 完成定义

本总体设计完成的标准不是立刻拥有五张地图，而是形成一个不会破坏当前开局内容、可以逐部分扩展的森林结构：

- 当前地图被明确识别为部分1“月痕前庭”。
- 其余四个部分拥有不同的区域职责和连接关系。
- 地图、剧情进度、资产和客户端布局都有稳定的分区边界。
- 任一后续部分都可以单独立项、制作、验证和回滚。
